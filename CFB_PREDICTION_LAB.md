## Install/integrate

Copy `cfb_model/` and `apply_integration.py` into the repository root.
Run `python apply_integration.py` there to apply both changes automatically
(backups `app.py.bak`, `sports_ui.py.bak` and, if present, `test_sports_ui.py.bak` are created). For manual integration: add `"CFB Model"` to `PAGES` in `sports_ui.py`, and insert the following
before the final `else:` that handles `Research` in `app.py`:

```python
elif page == "CFB Model":
    from cfb_model.ui import render_model_ui
    render_model_ui()
```

The original `requirements.txt` (Streamlit, pandas, requests) is sufficient.

For a completely separate app deployment, use `streamlit run cfb_model_app.py`.

## Load REAL data

1. **No key needed:** in the phone UI, choose **CFB Model → Public FBS scores → Load 2020–2026 public FBS scores**. Missing years, including the currently header-only 2022 season, are prominently warned about and excluded (not fabricated). For fully contiguous multi-year training, import the official CFBD API data. Data is downloaded from the public [jackwarfield/cfb_rankings](https://github.com/jackwarfield/cfb_rankings) season CSVs; this is a third-party resource and availability can change.
2. **Optional official CFBD source:** get a free token from https://collegefootballdata.com/ and set `CFBD_API_KEY` in Streamlit Secrets (`CFBD_API_KEY = "..."`), never in GitHub. Use **Fetch from CollegeFootballData → Fetch actual games** for 2018–2026.
3. Alternatively upload a CSV with all the columns shown in
   `data/columns_only_template.csv`, generated by the app. Every game must have a unique ID,
   timezone-stamped kickoff, completion flag and scores for completed games.
4. On a computer, offline CLI:

```bash
python -m pip install -r requirements.txt
# Free public history, no API key:
python -m cfb_model.cli sync-public --start 2020 --end 2026 --out data/fbs_public_games.csv
python -m cfb_model.cli backtest --games data/fbs_public_games.csv --holdout-year 2025
# Or use official CFBD data (requires a private CFBD_API_KEY):
export CFBD_API_KEY='YOUR_PRIVATE_KEY'
python -m cfb_model.cli sync --start 2018 --end 2026 --out data/cfbd_games.csv
python -m unittest discover -v -p 'test_*.py'
```

The model does not make up training scores. The distribution floors and parameters
are initial **baselines**, not calibrated to historical closes. Examine holdout MAE and Brier;
build a closing-line baseline and score probability calibration before using real money.

## Historical Kalshi quote backtest

Optional quote CSV columns: `game_id,captured_utc,outcome,line,ask_cents,shares,market_ticker,fee_multiplier`.
Use **only real archived, timestamped pre-kickoff prices**, and manually verify each
contract's rules. Outcome choices: HOME_WIN, AWAY_WIN, HOME_COVER, AWAY_COVER, OVER, UNDER.
For spreads, line means the **home team's handicap**. We only accept half-point lines
for spread/total backtests to avoid unsupported push settlement. One prespecified
snapshot per game/outcome/line prevents choosing the best historical price after the fact. If the model used a prior result that would have become available only AFTER the archived quote, the quote audit rejects the comparison. The result-availability fallback is kickoff plus 8 hours, not a claimed actual final whistle timestamp.

No quote history supplied => **no historical ROI claims**.

## Upcoming matchups (new)
1. On **CFB Model**, tap **Load 2020–2026 public FBS scores** to establish real historical scores and the corresponding ESPN team-ID mapping.
2. Tap **Load upcoming 8 days of FBS games**. The model makes one read-only, user-initiated request to ESPN's public FBS scoreboard; no key or extra AI service is needed.
3. The upcoming table includes only future pregame events with exact ESPN team IDs matching the FBS historical results. Unknown, started or malformed games are excluded. No fuzzy team-name matching.
4. Inspect projected margin, total and win probability under **Upcoming matchups**. These are uncalibrated baseline forecasts, **not verified positive-EV picks**.
5. ESPN's scoreboard is an undocumented third-party API and might become unavailable. Public game results can omit or misclassify fixtures. An empty or failed schedule does not imply no FBS games exist.

The public results source also lacks 2022. Its missing season is not filled or inferred. Historical profitability remains unproven; no betting or order placement is enabled.


### ESPN schedule compatibility (October 24, 2026)

ESPN now responds HTTP 400 when the scoreboard receives date ranges such as `dates=20261024-20261101`. The upcoming eight-day loader uses one bounded **single-day** request per UTC calendar date, deduplicates by exact event ID, and then filters to future pregame events inside the requested rolling horizon. Any failed or malformed daily request blocks the entire schedule rather than showing a partial slate as complete. No API key or sportsbook credits are needed. This is an unofficial ESPN endpoint, so responses can change.

## Indicative model vs sportsbook scoreboard (read-only, optional)

After loading the public score history and the upcoming ESPN scoreboard, **Model versus market — indicative research** displays point-based differences when that scoreboard happens to include a sportsbook spread or total with enough metadata to identify the correct home/away side. A spread difference is calculated as `projected_home_margin + market_home_handicap`; total difference is `projected_total - market_total`.

- The ESPN feed is undocumented and may omit odds. Missing book lines are shown as unavailable, not generated from the model.
- Bookmaker provider and snapshot time are preserved; snapshots older than 30 minutes show `STALE — NO SIGNAL`.
- If favorite/home direction is ambiguous, the market spread is withheld rather than applying a potentially reversed line.
- No transaction price, sportsbook vig, fee-adjusted edge, liquidity, odds or Kalshi settlement eligibility is inferred from an ESPN spread or total.
- Every mismatch is a **research lead only**. Validate injuries, lines, game clocks, model calibration, and contract rules before any real-money use. All live order placement remains disabled.


## Display time zone

The CFB Model's kickoff selector, upcoming slate, market comparison and snapshot labels use Central Time (`America/Chicago`; CDT or CST as appropriate). The app does **not** change game kickoff instants, eligibility checks or source timestamps. Exported history/prediction CSVs deliberately retain UTC for reproducible replay.

## Phase 2: probability calibration and historical sportsbook benchmark

The CFB Model now provides two audited, **paper-only** views for the selected holdout season:

**Probability calibration:** The 50–60%, 60–70%, 70–80%, 80–90%, and 90–100% forecast-confidence bands show the observed share of correctly picked outright winners. Do not treat these bins as 2025 betting profitability or as proof of calibrated spreads and totals.

**Historical sportsbook benchmark:** Obtain *real* CollegeFootballData historical /lines records using a private `CFBD_API_KEY` stored in Streamlit Secrets, or upload a verified CSV with these column headers:

`game_id,home_team,away_team,provider,home_handicap,total`

- `home_handicap` is the **signed HOME team's handicap**, e.g. Illinois +9.5 against Oregon -9.5 means `home_handicap = 9.5`.
- `total` is the reported betting game-total threshold (e.g. 49.5).
- At least one of `home_handicap` and `total` must exist for a game, and every `game_id` must be unique with one selected provider.
- The importer supports CFBD camelCase and snake_case JSON; a formatted spread is required to resolve home-vs-away sign. Ambiguous spreads are withheld instead of guessed.
- The 2025 lines **must match 2025 completed model games by exact game ID and exact team names**. If those data sources disagree, the benchmark blocks the mismatched records.
- The UI shows coverage, paired model-versus-book MAE and a naive game-resampling 95% interval, **not a verified prediction-market EV, ROI, CLV or historical win rate at actionable prices**. Some closing-line records have no captured-at timestamp or fill-depth data. This prevents a valid Kalshi P&L backtest.
- The public FBS game-score feed still has no 2022 season. A sourced, complete history is required before claiming validated performance.
- This feature **does not use the market as a model training input** and does not alter predictions, scanning, order placement or risk constraints. Market comparisons are held out from training.
